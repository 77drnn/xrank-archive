# X RANK ARCHIVE — Splatoon 3（Pシーズン限定）

スマホで閲覧できるスプラトゥーン3のXマッチランキング・アーカイブです。Pシーズン (`p-N`) だけを対象にし、ガチエリア・ガチヤグラ・ガチホコ・ガチアサリのランキングを収集します。フェス、ギア、スケジュール、サーモンラン等は収集しません。

## 追加したアーカイブ追跡

**初回からの履歴復元:** サイト公開後の観測だけに限定せず、公開元に残る過去のアーカイブをさかのぼって取り込みます。取り込み完了までは一部の日付しか表示されない場合がありますが、完了すると取得可能な過去スナップショットから名前の出現期間と順位・Xパワー推移を復元します。公開元に存在しない期間や、同じプレイヤーとして識別できない別IDの記録までは復元できません。

**既存バージョンからの更新:** 履歴ファイルをモバイル向けの32分割形式に変更しています。古い形式の `data/archive-state.json` を検出すると、派生履歴索引だけを削除して公開元のアーカイブを再インポートします。シーズン別ランキングのJSONは保持します。

- 公開元の `data/archive/` に保存された日付別マニフェストと `.tar.zst` を調べ、PシーズンのXランキングJSONだけを取り出します。
- 各日付のアーカイブから、シーズン・ルールごとの順位、Xパワー、名前、ブキを含む有効なランキングスナップショットを時刻付きで保存します。同一日の同じランキング状態は重複保存しません。
- アーカイブで確認された名前をプレイヤー識別子ごとに集計し、最初・最後に確認した日時、登場シーズンとルールを保存します。
- サイトには「過去の名前一覧」を追加しました。名前検索から過去の名前を使ってプレイヤーを開き、プロフィール内の名前履歴、アーカイブ由来の順位・XP推移を見られます。
- 初回の過去データ取り込みは自動で始まり、GitHub Actionsの1回の実行で最大30分間、マニフェストを処理します。各日付の処理後に進捗を保存し、時間予算に達すると安全に停止して次回へ続けます。新しい日付のアーカイブを優先し、その後は未処理の古い日付へ遡ります。サイトには取り込み済み日数と進捗が表示されます。
- 最新の公開Pシーズンランキングは毎時チェックし、ランキング内容に変化があったときは時間別スナップショットを保存します（直近90日分）。

**重要な制約:** アーカイブは公開元に残っている日付・ファイルに限られます。過去の名前は、その名前とプレイヤー識別子が同じ記録に含まれていた場合に結び付けられます。ID形式が変わったり、同じ識別子が過去データに見つからない場合、別名を完全に同じプレイヤーへ統合できないことがあります。また、保存された各時刻はアーカイブ内に収録された時刻であり、1時間ごとの全対戦記録ではありません。

## 公開：スマホからアクセスし、PCを止めても収集

このプロジェクトには GitHub Pages と GitHub Actions の設定が含まれています。GitHub側で収集するので自宅PCやスマホ、サイトを開いたままにする必要はありません。初期取り込み中も取り込めた履歴から順次サイトに公開されます。

1. GitHubで**新しい公開リポジトリ**を作成します（ブランチ名 `main`）。
2. ZIPを展開し、中のファイルをリポジトリのルートにアップロードします。`.github/workflows/xrank-site.yml` と `requirements.txt` も含めてください。
3. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。
4. **Settings → Actions → General → Workflow permissions** に `Read and write permissions` がある場合は有効にします。収集JSONの自動コミットに必要です。
5. **Actions** → `Collect P-season X rankings and publish site` → **Run workflow** を実行します。
6. 初回実行では公開元の全日付一覧を作り、1回最大30分間のバックフィルを自動開始します。最新側のアーカイブを先に取り込み、その後に古い日付を処理します。毎時のスケジュールで途中から自動再開し、サイト上の進捗表示が100%になると初回取り込み完了です。全期間の量と公開元の応答速度によっては、完了まで複数日かかることがあります。
7. `deploy-pages` が成功するとサイトURLが表示されます。スマホで開き、ブラウザメニューから「ホーム画面に追加」できます。

スケジュールはUTC基準で、GitHub側の混雑で遅れる場合があります。毎時ちょうどの実行を保証するものではありません。過去アーカイブの全件取り込みを手動で再開したい場合は、同じワークフローの `backfill_archive` オプションを有効にして実行してください。

## ローカルで動かす

Python 3.9以降を用意し、プロジェクトフォルダで次を実行します。

```bash
python -m pip install -r requirements.txt
python update_xrank.py
python prepare_site.py
python -m http.server 8000
```

ブラウザで `http://127.0.0.1:8000/public/` を開きます。初回のアーカイブ取り込みは1回最大30分で止まり、`data/archive-state.json` に進捗が記録されます。続きを取り込むには `python update_xrank.py --backfill-archive` を再実行してください。ローカルで定期収集を続ける場合はPCとスクリプトを動かし続ける必要があります。PCを止めても収集したい場合はGitHub Actions方式を使ってください。

## 保存先

- `data/seasons/p-N/`: Pシーズンごとに、4ルールの最新公開ランキングJSON
- `data/hourly/p-N/<rule>/YYYY-MM.jsonl`: 現行シーズンで変化があったランキングの時間別履歴（90日間）
- `data/archive-history/p-N/<rule>/YYYY-MM-sNN.jsonl`: プレイヤー識別子のハッシュで32分割した順位・Xパワーの時刻付きスナップショット（スマホで履歴を軽く読むため）
- `data/archive-name-events/YYYY-MM.jsonl`: 各日付の全有効スナップショットから抽出した名前の出現記録
- `data/player-names-index.json`: 過去の名前、初回・最終確認日時、季節・ルールの索引
- `data/archive-state.json`, `data/archive-index.json`: アーカイブの取り込み進捗と一覧
- `data/archive-manifest-catalog.json`: 過去アーカイブの日付カタログ（収集負荷を抑えるため日次で更新）

## ほかの収集方法

1. **公開JSONと公開アーカイブ（標準）**：認証情報なしで利用できます。公開元の形式が変わるとスクリプトの修正が必要です。
2. **クラウドのCronジョブ＋オブジェクトストレージ**：履歴を大規模に長期間保存するなら、別のクラウド保管に切り替えられます。初期設定はGitHub Actions方式より難しめです。
3. **SplatNet 3経由**：アカウント認証セッションやAPI変更に依存します。公開ランキングの収集だけなら、認証不要の公開データを使う方式のほうが簡単です。

## ファイル

- `update_xrank.py`: Pシーズンランキングと公開アーカイブの取得・履歴保存
- `requirements.txt`: `.tar.zst` 読み取り用ライブラリ
- `prepare_site.py`: GitHub Pages用サイトの準備
- `.github/workflows/xrank-site.yml`: 毎時収集・自動公開
- `index.html`, `style.css`, `app.js`: スマホ対応Webアプリ
- `data/`: 取得済みJSONと履歴

非公式ファンツールです。任天堂とは関係ありません。

## 全期間最高Xパワーランキング（追加機能）

サイトの「全期間最高Xパワーランキング」では、Pシーズンの取得可能な全期間を横断して、プレイヤーごとの最高記録をXパワー順に表示します。

- ガチエリア・ガチヤグラ・ガチホコ・ガチアサリは、それぞれプレイヤーごとの最大観測Xパワーを集計し、上位500人を表示します。
- 「総合」は、1人につき4ルールの最高記録のうち最も高いXパワーを1件採用し、重複を除いて上位1000人を表示します。4ルールの平均値や合計値ではありません。
- 同じ最高XPが複数回観測された場合は、アーカイブで最初に確認された最高記録の日時を残します。並び順はXP降順、記録時の順位、プレイヤー識別子の順です。
- 日付付きアーカイブの記録を優先し、アーカイブに時刻がないシーズン別ランキングJSONは補完データとして使います。補完データ由来の日時は「日時未収録」と表示します。
- `data/all-time-archive-max.json` は全期間のプレイヤー別最高値を保持する内部キャッシュです。処理時間を抑えるためリポジトリには保存しますが、GitHub Pagesの公開ファイルからは除外します。
- `data/all-time-ranking.json` はサイトが利用する上位500/1000人の公開用ランキングです。新しいアーカイブが取り込まれると再計算されます。

全期間ランキングの初回構築は、過去アーカイブの初回バックフィル進捗に応じて段階的に増えます。バックフィルが完了する前の順位は暫定値です。公開元に残っていない記録や、個人識別子が異なり同一人物と判定できない記録は自動統合できません。
